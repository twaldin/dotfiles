Start with the project's existing UI, design tokens, components, framework versions, and requested outcome. Reuse that language and structure. For new designs, establish a clear visual direction suited to the product.

Read only the references needed for this task:

- **UI behavior and visual quality:** [UI guide](references/ui.md).
- **React/Next.js performance:** [Vercel index](../../vendor/vercel-agent-skills/skills/react-best-practices/SKILL.md), then the relevant individual rule files.
- **React component APIs and state ownership:** [Vercel composition index](../../vendor/vercel-agent-skills/skills/composition-patterns/SKILL.md), then the relevant individual rule files.

Apply framework-specific advice only when it fits the installed version and project architecture. The reference collections are a menu of techniques, not a request to apply every rule or change libraries.

Use the [browser guide](../browser/SKILL.md) for inspecting the running UI. Compare the relevant interaction states and layouts with the requested behavior or design. Distinguish what was visually checked from what was only inspected in code.
